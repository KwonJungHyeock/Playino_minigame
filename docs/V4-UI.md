# v4 화면 표시(HUD) 원칙 — 콘솔 게임 방식

공통 구현: `src/gfx3d/hud.js` (+ 대화 얼굴 `portrait.js`). 모든 v4 미션이 같은 진행창 · 대화 · 배너 · 결과창을 쓴다.

## 조사에서 가져온 것

- **늘 떠 있는 정보는 최소로, 필요할 때만 꺼낸다.** 최근 콘솔 대작은 화면 위 고정 정보(체력 · 점수판)를 줄이고, 상황에 맞춰 잠깐 보여 주거나 게임 세계 안에 녹이는 쪽으로 옮겨 왔다(2014~2025 올해의 게임 후보 30편 분석, 본 대학 연구). 플레이어도 그런 화면을 더 몰입되게 느꼈다.
- **안내는 장면 안에서.** 아스트로봇은 화살표 대신 반짝이는 물체 · 소리 · 진동으로 길을 알려 준다 → 우리도 판정 글자 · 콤보를 장면 속 그 자리(판정 고리 위)에 짧게 띄운다.
- **대화 상자 4요소**: 화자 이름 · 얼굴 · 본문 · 넘김 표시. 글자는 읽기 좋은 속도로 한 글자씩, 누르면 바로 다 보이고 한 번 더 누르면 다음.
- **조작 표시는 지금 쓰는 입력에 맞춘다**(키보드면 스페이스, 터치면 버튼).
- **글자는 크게, 화면 가장자리는 비운다**: 본문 16px 이상(우리는 대화 19px · 큰 제목 Jua), 중요한 글자 · 버튼은 화면 안쪽 90%(안전 영역).
- **색만으로 구분하지 않는다**: 판정은 색 + 글자(PERFECT/GOOD/MISS) + 소리 + 실제 LED 위치(초록 D2 · 노랑 D3 · 빨강 D4).
- **피드백은 짧고 건너뛸 수 있게**: 아이들 학습 게임에서 정답 연출이 길면 흐름을 끊는다는 사례 → 배너 1.5~2초, 인트로 · 대화는 건너뛰기.
- **결과창은 결론 하나 + 다음 행동 하나**: 별 · 등급 도장 → 수치 3개 → [다시 하기] [계속].
- **실패를 벌하지 않는다**: 마리오 오디세이가 목숨 · 게임오버를 없앤 것처럼, 실패해도 "다시 접근 중…" 으로 이야기를 이어 간다.

## 우리 규칙

| 요소 | 위치 | 언제 |
|---|---|---|
| 미션 목표 카드(아이콘 · 미션 이름 · 목표 1줄 · 진행 막대) | 좌상단 | 준비 이후 계속, 목표만 바뀜 |
| 일시정지 | 우상단 | 항상 (Esc 도 같음) |
| 대화 상자(얼굴 · 이름표 · 한 글자씩 · ▼) | 하단 가운데 | 이야기 장면 |
| 큰 행동 버튼(조작 표시 + 동작 이름) | 하단 가운데 | 플레이 중에만 |
| 판정 글자 · 콤보 | 장면 속 그 자리 | 입력 순간 0.6초 |
| 배너(MISSION START / CLEAR / TRY AGAIN) | 화면 1/3 | 단계 전환 1.5~2초 |
| 카운트다운 3 · 2 · 1 · GO | 가운데 | 시작 직전 |
| 알림(보드 연결 등) | 상단 가운데 | 3초 자동 사라짐, 최대 2개 |
| 창(결선 · 설명 · 결과 · 일시정지) | 가운데 | 주 버튼에 스페이스, 뜬 직후 0.4초는 키 무시(연타로 지나가지 않게) |
| 허브 미션 진입(홀로그램 브리핑) | 장면 안(문 원판 위) + 바이저 꺾쇠 · 정보 3줄 · 한마디 · 출발 버튼 | 문 원판에 멈출 때. 창 · 카드 없이, 꾹 눌러 출발(0.8초). 브리핑 중엔 목표 칸 · 다른 안내판이 비켜 준다 |

- 글꼴: 제목 · 버튼 · 숫자 **Jua**(둥근 손글씨 느낌), 본문 **Noto Sans KR**.
- 색: 밤하늘 유리판(반투명 남색 + 흐림) · 겨자 금색 강조 · LED 민트. 좋음 초록 · 주의 노랑 · 실패 빨강은 의미색으로만.
- 움직임: 튀어 오르듯 들어오고(살짝 넘침) 부드럽게 사라짐. 움직임 줄이기 설정이면 즉시 표시.
