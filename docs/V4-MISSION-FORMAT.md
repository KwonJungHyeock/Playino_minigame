# v4 미션 짜임새 — 모든 미션이 같은 리듬으로

닌텐도 게임이 처음 한 판만 해 보면 나머지가 저절로 손에 익는 건, 판마다 **같은 문법**을 쓰기 때문이다.
v4 의 미션 10개도 같은 박자 · 같은 화면 언어 · 같은 조작을 쓴다. 새 미션은 이 문서를 먼저 채우고 만든다.

## 한 미션의 8박자

| # | 박자 | 하는 일 | 시간 | 만드는 곳 |
|---|---|---|---|---|
| 1 | 도착 | 기지 미션 문에서 꾹 눌러 출발 → 원 전환 → 미션 장소로 카메라 하강 | 5초 이내 · 건너뛰기 | `hub3d.js` · 각 미션 `intro()` |
| 2 | 사연 | 바이저봇 2~3마디: 왜 왔나(이야기) · 무엇을 얻나(로켓 부품) | 3마디 이하 | `hud.dialogue` |
| 3 | 결선 준비 | 핀 그림 + 보드 연결 + 부품 테스트. 보드가 없어도 진행 | — | `hud.window` |
| 4 | **바이저 강의** | 카드 3장 · 한 장에 생각 하나 · 진짜 아두이노 코드 2~3줄 + 눌러 보는 단추 → 3D 장면과 보드에서 바로 실행 | 처음 한 번만 자동, 다음부턴 '원리 다시 보기' | `gfx3d/lesson.js` |
| 5 | **확인 퀴즈** | 3문항 · 3지선다 · 답 자리 섞기. 틀리면 힌트 후 다시(탓하지 않음), 맞히면 그 코드가 장면에서 실행. 메달과 무관 | 1분 안팎 | `gfx3d/lesson.js` |
| 6 | 1단계 | 핵심 조작 하나를 익힌다. 판정 · 통과 기준(A등급 85%↑)은 2D 판과 같다 | 1~2분 | 각 미션 |
| 7 | 2단계 | 같은 원리, 새 비틀기(리믹스) — 1단계를 확장한 놀이 | 1~2분 | 각 미션 |
| 8 | 보상 | 장면 안에서 부품이 나타난다 → 기지로 → 로켓에 장착 연출 | — | 각 미션 + `hub3d.js celebrate` |

- 실패는 막지 않는다: 1단계를 못 넘겨도 2단계로 갈 수 있다. 메달만 두 단계 A등급이 필요하다.
- 결과 기록 이름(`results.record(id, { summary })`)은 2D 판 단계 이름과 반드시 같게 — 다르면 메달 판정이 깨진다. 이름은 `content/v4story.js` 의 `stages`.

## 강의 · 퀴즈 쓰는 법 (`runLesson`)

```js
const L = runLesson(el, {
  cards: [{ title, say, code: ['digitalWrite(3, HIGH);  // 켜짐'], acts: [{ code: 'HIGH', label: '켜기', color, line: 0, run: () => 장면에서실행() }], after }],
  quiz:  [{ q, code?, options: [{ code } | { label }], answer, hint, good, onRight, runLine? }],
  outro, skippable: true, sfx,
});
const r = await L.done;   // { right, total, firstTry, skipped }
```

- 카드의 `say` 는 25자 안팎 두 문장까지. 원리 이름(디지털 출력 등)은 단추를 눌러 본 **뒤에** `after` 로 알려 준다 — 해 보고 이름 붙이기.
- 단추는 반드시 장면을 움직인다(유도등이 켜지고 · 부저가 울리고 · 색이 섞이고). 보드가 연결돼 있으면 진짜 부품도.
- 퀴즈 오답 힌트는 정답을 말하지 않고 강의 카드의 한 줄을 떠올리게 한다.
- 본 기록: `localStorage['eduino.v4.lesson.v1'][방 ID]` (정답 수 · 첫 시도 정답 수).

## 미션별 강의 · 퀴즈 내용

| 방 | 강의 카드 3장 | 퀴즈 3문항 |
|---|---|---|
| led 착륙 유도등 | HIGH/LOW(켜짐·꺼짐) · 핀 번호 = 유도등 주소 · delay 로 박자 | 3번 핀 켜는 코드 · LOW 의 뜻 · 1초 = delay(1000) **(완료)** |
| buzzer 구조 신호 비콘 | tone(핀, 주파수) · 주파수 = 음 높이 · 소리 길이와 쉼(delay · noTone) | 높은 음은 큰 숫자 · 소리 끄기 · 주파수의 뜻 **(완료)** |
| rgb 에너지 셀 | 빛의 삼원색 · setPixelColor 0~255 세기(보드의 풀 컬러 LED 는 WS2812 라 analogWrite 가 아니다) · 섞으면 새 색 | 빨강+초록 · 255 의 뜻 · 끄는 코드 **(완료)** |
| cds 태양광 충전소 | analogRead 0~1023 · 밝으면 값이 커짐 · if 로 기준 넘기 | 가리면 값은? · 값의 범위 · 기준값 고르기 |
| pot 로버 추력 | 다이얼 = 가변저항 · analogRead · map() 으로 범위 바꾸기 | 끝까지 돌리면 · map 의 쓰임 · 가운데 값 |
| button 운석 방어막 | digitalRead · 눌림 = HIGH/LOW · if 로 반응 | 눌렀을 때 값 · if 쓰임 · 두 버튼 구분 |
| lamp 어둠 동굴 | 입력 → 처리 → 출력 · 조도값으로 색 정하기 | 흐름 순서 · 어두울 때 색 · 값 비교 |
| bomb 원자로 | 다이얼 값 → LED 깜빡 빠르기 · 정밀하게 맞추기 | 값과 속도 · 범위 · 조건 |
| final 발사 쇼 | 배운 부품 묶기 · 순서대로 실행(시퀀스) | 종합 |

## 공통 화면 · 조작 언어

- 화면 원칙은 `docs/V4-UI.md`. 상자 · 모달 대신 **바이저 판독 띠**(왼쪽 빛줄 + 오른쪽으로 사라지는 짙은 유리), 정보는 장면 안에.
- 단추는 **둥근 비닐 알약/단추**(크림색 몸 + 색 캡, 누르면 4px 들어감) — 유도등 단추 · 강의 단추 · 출발 단추가 같은 결.
- 조작: 숫자 1·2·3 = 고르기/연주, 스페이스 = 진행/신호, Esc = 일시정지. 터치에선 키 표시를 숨긴다.
- 색: 초록 D2 · 노랑 D3 · 빨강 D4 는 미션이 바뀌어도 같은 뜻으로 쓴다(정확 · 좋음 · 놓침).
- 소리: 다가감(hover) · 누름(click) · 정답/정확(perfect) · 좋음(ok) · 아쉬움(no) · 홀로그램(holo) · 출발(launch). 모든 입력은 0.1초 안에 소리 + 그림으로 답한다.
- 3D 화면은 가림막 뒤에서 준비(`stage` 의 `hold` · `warm()` · `reveal()`) — 덜 지은 장면이 보이지 않게.

## 게임 형태는 미션마다 달라야 한다

같은 '떨어지는 걸 맞춰 누르기' 가 반복되면 지루하다. 센서의 성질이 곧 게임의 손맛이 되게 고른다.

| 미션 | 센서 | 게임 형태 | 핵심 손맛 |
|---|---|---|---|
| 01 착륙 유도등 | LED(출력) | 타이밍 착륙 · 별자리 연주 | 박자 · 리듬 **(완료)** |
| 02 구조 신호 비콘 | 부저(출력) | 높이가 다른 신호선 리듬 | 소리 높이 = 줄 높이 **(완료)** |
| 03 에너지 셀 | RGB(출력) | **조합 퍼즐** — 빛 세 줄기를 섞어 셀 색 맞추기, 시간 압박 대신 정확도 | 섞는 손맛 **(완료)** |
| 04 태양광 충전소 | 조도(입력) | **실시간 조종** — 손 그림자로 태양판 각도를 움직여 빛 따라가기 | 손을 움직이는 몸짓 |
| 05 로버 추력 | 가변저항(입력) | **운전 · 균형** — 다이얼로 로버 속도를 조절해 협곡 통과(너무 빠르면 미끄러짐) | 미세 조절 |
| 06 운석 방어막 | 버튼 2(입력) | **반응 · 방어** — 좌우 방어막을 버튼으로 들어 운석 막기 | 순발력 |
| 07 어둠 동굴 | 조도 + RGB | **탐험** — 손전등 밝기로 동굴을 비추며 수정 찾기 | 탐색 · 발견 |
| 08 원자로 | 가변저항 + LED | **긴장 유지** — 들끓는 노심을 다이얼로 안정 구간에 붙잡기 | 버티기 |
| 도전 챌린지 | 없음 | **캐릭터 조작 장애물 달리기**(폴가이즈식) | 점프 · 다이브 · 몸싸움 **(완료)** |

## 자유 도전 — 센서 없이 몸으로

- 보드 없이도 하는 캐릭터 조작 모드. 커리큘럼 방이 아니라 메달 · 진도와 따로(`app/bonus.js`).
- 깨면 **보너스 부품** → 기지 로켓의 보너스 칸에 붙고, 마지막 탈출(발사 쇼)에서 이점: 부스터 날개 = 실수 1번 보호.
- 조작 문법은 모든 자유 도전에서 같게: 이동(WASD · 방향키 · 왼쪽 조이스틱) · 점프(스페이스 · 점프 단추) · 다이브(Shift · 다이브 단추) · 체크포인트로(R).
- 손맛 규칙: 코요테 타임 0.12초 · 점프 미리 누르기 0.14초 · 착지 스쿼시 · 넉백 경직 0.55초 · 떨어지면 0.4초 안에 체크포인트로(벌주지 않기) · 물리는 1/60초 고정 단계(느린 기기에서도 같게).
- 몸짓 규칙(통통 · 말랑): 몸짓은 보이는 마디에서만(판정 불변) · 점프 늘어남 / 착지 납작 + 젤리 출렁 · 맞으면 데굴 → 털썩 · 다이브는 배 미끄럼 · 떨어지면 다시 '퐁'. 소리도 같이: boing · plop · bump · whee · 팡파르(`app/sfx.js`)

## 서체 (`gfx3d/type.js` — 앱에 넣어 둔 OFL 글꼴, 외부 글꼴 서버 없음)

| 쓰임 | 서체 | 처리 |
|---|---|---|
| 큰 제목 · 미션 이름 · 배너 · 안내판 | **Jua** (둥글고 통통한 한글 — 비닐 장난감 결) | 게임 로고 글자: 남색(#1b1f4a) 외곽선 + 아래로 입체 그림자 + 위가 밝은 그라데이션(캔버스) |
| 본문 · 대사 · 설명 · 작은 글씨 | **Pretendard** | 받침 띠(짙은 유리) 위에 흰 글자 |
| 숫자 · 영문 표기(MISSION 01 · 3/8 · 카운트다운 · 콤보 · 등급) | **Fredoka** (둥근 라틴) | 큰 숫자는 로고 글자 처리 |
| 코드 | **JetBrains Mono** | 함수 노랑 · 숫자 청록 · HIGH/LOW 주황 |

- 새 화면에서 `"Noto Sans KR"` 이나 시스템 글꼴을 직접 쓰지 않는다. CSS 는 `var(--f-display|--f-ui|--f-num|--f-code)`, 캔버스는 `FONT.*` + `fontsReady()` 뒤에 그린다.
- 로고 글자 클래스: `.t-logo`(흰) · `.t-logo.gold` · 숫자 `.t-num`.

## 감동 디테일 점검표 (새 미션을 내보내기 전에)

- [ ] 첫 5초 안에 '여기가 어디고 왜 왔는지' 가 그림으로 보인다
- [ ] 단추를 누르면 장면(과 보드)에서 실제로 무언가 일어난다
- [ ] 성공마다 작은 축하(소리 · 반짝 · 바이저봇 표정), 큰 성공엔 큰 축하
- [ ] 실패 문구가 탓하지 않고 다음 행동을 알려 준다
- [ ] 화면마다 다음 행동이 하나만 크게 보인다
- [ ] 휴대폰 390px · 터치에서 겹치는 것이 없다 / 키보드만으로도 끝까지 간다
- [ ] 다시 들어와도 메모리가 쌓이지 않는다(`renderer.info.memory`)
- [ ] 기록 이름이 2D 판과 같다(메달 판정)
